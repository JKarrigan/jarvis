## Architecture

This is a Next.js 16 App Router app for the home: **Air** (`app/(air)/**`: air quality, Hue lights, system) and **Media / "Reel"** (`app/media/**`: Jellyfin movies, TV, audiobooks, books, the family **Photos** library and **Documents**). It runs on a Raspberry Pi; everything irreplaceable lives on the Synology NAS (Jellyfin libraries, the photo and documents shares), the Pi only indexes, serves and caches.

### App shell

The root layout owns metadata (title template `%s · Home`), the `viewport` export, the PWA bits (`app/manifest.ts`, `app/icon.png`, `app/apple-icon.png`, `public/icons/`) and `<MotionConfig reducedMotion="user">`; reduced motion for CSS animations is handled in `globals.css`. `app/global-error.tsx`, `app/(air)/error.tsx` and `app/media/{error,loading,not-found}.tsx` are the boundaries. `AppSwitch` (`app/_components/AppSwitch.tsx`, the Home / Media segmented control) is the only bridge between the two apps; it is part of each app's own chrome, not a floating element. Both apps share one chrome shape: from `md` a sidebar that is an icon rail until `xl` and a 232px labelled sidebar from there (`AirSidebar.tsx`; `media/MediaRail.tsx`, where pages follow the width through `--rail`), and on phones an in-flow top bar with the switch plus a fixed bottom tab bar. Home pages are built from `app/_components/air/ui.tsx` (`Page`, `PageHeader`, `Card`, `Segmented`, `StatusDot`, button/input classes) on the `air-*` colour tokens in `globals.css`; the `(air)` layout owns the page background and the tab-bar padding, so pages never set `min-h-screen` or a background. The eight metric pages hang off Air quality (tiles link to `/measurement/<slug>`, which has its own metric switcher), not off the nav. The labelled sidebar can be collapsed to the rail (`SidebarToggle.tsx`, `[` key): the choice is per device in `localStorage` (`home.sidebar.v1`, `lib/sidebar.ts`), applied before first paint by an inline script in the root layout as `html[data-sidebar="collapsed"]`, and everything else is CSS: use the `wide:` variant (xl and not collapsed, defined in `globals.css`) instead of `xl:` for anything that depends on the labelled sidebar. The Media sidebar stays translucent so artwork shows through it. Collapsing animates: the sidebar's width, the labels (kept in the DOM and faded, with icons at a fixed offset so nothing jumps) and `--rail`, which is registered with `@property` so every gutter that uses it eases too. On the rail `AppSwitch` is a single button with a dropdown, portalled to `<body>` because the sidebar clips its overflow. Shared accessible dialog primitives (`Modal`, `Drawer`, `Sheet`: role=dialog, focus trap, Escape handled by the top-most dialog only, which calls `preventDefault` — window-level Escape listeners must check `e.defaultPrevented`) live in `app/_components/lights/dialog.tsx` and are re-exported from `HueControls.tsx`. `lib/http.ts` has the request helpers every API route uses: `assertSameOrigin` (called first in every mutating handler — the app has no auth, this is the CSRF/DNS-rebinding defence; never put it in `proxy.ts`), `intParam`/`numParam`, `isLanHost`, `parseRange`, `readJson`.

### Data flow

1. **Startup** — `instrumentation.ts` (Node.js runtime only) calls `startBackgroundJobs()` in `lib/startup.ts`, which starts the poller from the saved device host (`settings` key `ag.deviceHost`, saved by `POST /api/device`, else `DEVICE_HOST`), prunes hourly (readings 30 d, but never rows not yet rolled up; `readings_5m` 400 d; closed events 90 d), schedules `scheduleRollup()` and starts the photo scanner. For events it also runs `mergeDuplicateEvents()`, then `refreshStoredEvents()` (re-derives type, severity and wording of every stored row with the current rules, since events outlive the readings they came from), and schedules `scheduleTraceBackfill()`. Nothing waits for a browser any more.
2. **Server poller** (`lib/poller.ts`) — a `globalThis` singleton (hot-reload safe) running a `setTimeout` chain with an in-flight guard, fetching `/measures/current` every 10 s, validating the payload (`insertReading` rejects junk) and writing rows via `lib/db.ts`. After each stored reading `rollupIfDue` schedules `rollupReadings()` once a five-minute bucket has been over for 60 s; `scheduleRollup()` (like `scheduleTraceBackfill`) repeats every 2 s while a backlog remains (the first start on an existing db works through weeks, a day of readings per run). **Event detection runs here**, server-side: `lib/eventDetection.ts` is one incremental `EventDetector` (1-minute wall-clock grid, id `${type}_${startMs}` created once at onset and never changed, baseline frozen at onset, closes after 5 clear minutes, per-gap warm-up). **One incident is one row:** there are two slots, `sample` (combustion, fuel vapour, outdoor drift, VOC, particulate) and `vent` (CO₂, with hysteresis: it opens at 1000 ppm held for 30 min, but an open one is held by the same test at `co2Release` 900 ppm, so a room hovering around 1000 is one event; reopening needs 1000 again); while a slot's event is open any of its rules keeps it going and the event takes the most serious type it has shown (`moreSerious`: severity for the incident's sustained level, then rule order; the id prefix is the *onset* type and `type` can differ; the upsert updates `type`). A dismissal is sticky until the severity rises, which clears it, and dashboard toasts are keyed by id + severity, so an escalation alerts again, and matching readings within 15 min of the last matching ones reopen it whatever the type. On restart `primeDetector` replays the last 6 h and `resume()` continues the open rows per slot (stale rows skipped first; the row's id and start time win), restoring the stored baseline when the replay alone can't see the incident; `reconcileOpenEvents` then writes those and closes the rest. Batch reprocess replays readings through the same detector and replaces only events starting once a fresh detector can evaluate (readings start + 33 min; older events outlive the 30-day readings), keeping acknowledgements across type changes within a slot; `replaceLiveDetector` then re-points the live detector at the surviving ids. `mergeDuplicateEvents()` (startup and after reprocess) collapses rows older detectors split per classification change or wrote every 10 s, copying the originals to `events_premerge` first. Clients only read `/api/events` (and can dismiss or delete: see **Events** below).
3. **SQLite** (`lib/db.ts`) — `globalThis` singleton (`better-sqlite3`; external by default in Next, no config needed). Tables: `readings(id, timestamp, data TEXT)` (JSON `DeviceMeasures`), `settings(key, value)`, `events` (with a nullable `trace` JSON column, added by `ALTER TABLE` in `getDb()` on older databases), `readings_5m` (the rollup, below), plus the photo tables. **Rollup:** `readings_5m(bucket, n, t_avg, <field>_avg/_min/_max)` for every `NUMERIC_FIELDS` entry (columns generated from that list, missing ones added on open), complete buckets only (end ≥ 60 s ago), written oldest first and never rewritten, so raw rows after `MAX(bucket) + 5 min` are exactly the un-rolled ones; kept 400 days, and `pruneReadings` only deletes raw rows before the end of the last rolled bucket. `getHistory` returns raw rows for spans ≤ 6 h; above that ≤ ~800 buckets with `min`/`max` per field: buckets under 5 min are averaged from raw rows (finished ones cached per bucket size), longer ones (7 d and up) are rounded up to a multiple of 5 min and combined from `readings_5m` (`n`-weighted) plus the raw rows not rolled up yet, uncached (~10 ms). `/api/daily-summary` reads only `readings_5m` (`lib/dailySummary.ts`, open day lags ≤ ~6 min). `getRecentMinutes` is the one-minute hydrate (`/api/history?minutes=`): the last N minutes up to the newest reading, each stamped with its minute's last reading, rounded to 2 decimals.
4. **API routes** (`app/api/`) — thin wrappers around `lib/*`. No auth (LAN only) but every mutating route calls `assertSameOrigin`, every numeric input goes through `intParam`/`numParam`, and errors are generic (`{ error }`, real status codes; details only in the server log).
5. **PollingProvider** (`app/_components/PollingProvider.tsx`, mounted in `app/(air)/layout.tsx` so media pages don't poll) — client context hydrating `history` from `/api/history?minutes=600` (one-minute averages, ~150 kB instead of 1.2 MB of raw rows), then polling `/api/latest` every 10 s (setTimeout chain, paused while the tab is hidden, fills gaps after one) and appending raw readings; `history` is the last 10 h by time, so its consumers (sparklines, `getTrend`, the Overview chart's gap detection) are time-based, never index-based. `measures`/`lastUpdated` only ever come from `/api/latest` (a raw reading with `model`/`firmware`), never from `history`. It also polls `/api/events` every 30 s (the last 7 days plus anything open; `alerts` = open warnings and criticals nobody has dismissed, which is what the banner, toasts and sidebar badge show); reads its localStorage settings through `useSyncExternalStore` (cross-tab). The server is the source of truth for the device host. `lib/useNow.ts` (clocks, `STALE_AFTER_MS`) + `Clock.tsx` keep the per-second clock out of the dashboard render; `StaleBanner.tsx` greys values when data is > 60 s old.
6. **Pages** — Overview (`/`, `HomeDashboardShell` → `HomeDashboard`): the wall-display layout, with the hero clock, the AQI sentence, a hairline metric strip (`MetricStrip`) and room tiles whose whole surface is the on/off switch. Air quality (`/air-quality`, `DashboardShell` → `Dashboard`): `AqiSummary`, 8 `MetricCard` tiles (memoized) and history charts (1 h to 1 y; time-based x-axis, lines break at gaps; downsampled ranges draw each bucket's min-to-max band behind the line and hover reads `avg (min to max)`; the measurement page's Lowest / Highest use those true extremes). Metric numbers stay neutral; colour sits on the status word, and a tile is only tinted when its reading leaves the good range. Events (`/events`, `/events/[id]`) are described below.

### Events

What an event is called, how serious it is and how it is worded all come from **`lib/eventInfo.ts`** (pure, client-safe; the detector, the API and every component read it, so never copy a label, severity colour or threshold into a component). The detector's rules (`lib/eventDetection.ts`) only decide *when* an incident is open; `buildEvent` then asks `eventInfo`:

- **Names say what was measured**, never a guessed cause: Particle spike, VOC rise (`voc_event` and `fuel_vapor` are one kind: the sensor cannot tell fuel from cooking), Combustion fumes, Outdoor pollution, Stale air. Causes are listed as possibilities.
- **Severity is how bad the air got**, judged on `sustained` (`events.sustained`, JSON): per reading, the highest 3-minute median on the detector's minute grid since the incident began, so one stray 10 s reading cannot lift a band. `peak` stays the true maximum for charts and sentences; rows from older versions have no `sustained` and are judged on `peak`. `events_premerge` keeps the original 14 columns (it already exists on the Pi in that shape, so `PREMERGE_COLUMNS` in `lib/db.ts` is separate from `EVENT_COLUMNS`). The bands (`SEVERITY_LIMITS`): PM2.5 ≥ 55.5 warning, ≥ 125.5 critical; CO₂ ≥ 1500 warning, ≥ 2000 critical; the combustion pattern is at least a warning and critical with a NOx index ≥ 20; **VOC alone is always notable** (the index is relative and reaches 500 during ordinary cooking). On three weeks of real readings this turned 20 "critical" evenings into 2. `classifyEvent` renames a VOC rise to a particle spike once PM2.5 is in the Unhealthy range (the VOC rules are checked first, so they would otherwise mask smoke); the id keeps the onset type.
- **Alerts** are warnings and criticals (`isAlert`). `EventBanner` (Overview and Air quality, animated, live reading, Dismiss) and `EventAlerts` (toasts on every Home page, mounted in `app/(air)/layout.tsx`, once per id + severity via `localStorage` `aq-notified`, not on the banner pages) both read `usePolling().alerts`. Dismissing = `PATCH /api/events/[id] { acknowledged: true }`, sticky until the severity rises. Notable events are logged only.
- **Trace** (`EventTrace`, `events.trace`): ≤ 60 averaged buckets of the four detection readings from 15 min before to 15 min after, when each peaked, and minutes spent in each band. Saved when an event closes (`persistChanges` in the poller), backfilled in small batches for rows without one (`scheduleTraceBackfill`: startup, after a reprocess), computed on demand for an event still going, and reset to NULL by any write to the row. The JSON value `null` means "readings already gone, do not retry". Only `getEventById` returns it; lists (`getEvents`) leave it out. It is why an event older than the 30-day readings window still has a chart.
- **API**: `GET /api/events` (list, no traces); `GET /api/events/[id]` → `{ event (with trace), readings (empty once pruned), related: { newerId, olderId, overlapping (the other slot, CO₂ vs everything else), recent (same-slot starts in the 14 days before, for "this happens often") } }`; `PATCH` dismisses; `DELETE` removes a finished event (409 while it is open, because the detector would write it back; a reprocess brings a deleted event back if the readings still show it); `POST /api/events/reprocess`.
- **UI** (`app/_components/events/`): `EventBits.tsx` has the shared pieces (`SeverityMark`: ring / triangle / square so severity is never colour alone, `EventRow`, `DayTrack`, `KeyNumbers`, time formatting). `EventsLog.tsx` is a ledger of days: each day is a midnight-to-midnight track with its events underneath; 7 / 30 / 90-day range and the severity and kind filters live in the URL (`history.replaceState` with a fresh object, read through `useSearchParams`, hence the `Suspense` in the page). `EventDetail.tsx` + `EventLanes.tsx` stack the four readings on one time axis (raw device values, the same ones the rules saw; the event band, the lead reading's peak and a shared hover cursor run through every lane), with the facts, overlapping events and "this happens often" in a side column. `DetectionGuide.tsx` explains the rules from `KIND_INFO` and holds "Re-run detection". `confidence` is still stored but shown nowhere.

### Search by person

The global Search modal (`SearchModal.tsx`) fetches a compact index from `GET /api/media/search-index` when it opens (cached client-side for 60 s): titles, collections, audiobooks, ebooks and **people**. Credits (every director plus the top 8 billed actors per movie/show, `ReelCredit`) are **not** part of the catalog query: asking Jellyfin for `People` on the whole library takes ~6 s and pushes the response past Next's 2 MB cache cap, so they come from a separate paged `Fields=People` fetch memoized on `globalThis` (`getCreditsIndex`, 5 min TTL, stale-while-revalidate; on failure the catalog still renders without credits). `getCatalog()` merges them onto each `ReelTitle.people` **without** headshot URLs (the catalog is passed to library pages); the search-index route reads `getTitleCredits()` (with headshots) and aggregates people as `{ id, name, imageUrl, directed, acted }`, where `directed`/`acted` are indexes into `titles`. Search results list matching people first (avatar or initials, linking to `/media/person/[id]`) and, after the titles whose own name matches, the titles they're credited on ("Directed by …" / "With …").

The same credits drive the library pages (`library.tsx`, spec in `docs/media-library-redesign-spec.md`): a free-text filter over titles and names, Genre and Show, and a Filters popover with Type (on mixed views), Tag and searchable Director / Actor dropdowns (`allPeople` in `selectors.ts`); active filters show as removable chips. Someone who both directs and stars in a title holds one credit of each kind. Filters, sort, sort direction and view are mirrored to the URL (`libraryQuery.ts`, read with `useSearchParams`, written with `history.replaceState` and a fresh state object) so Back from a title restores the list; Grid / List and poster size are per-profile preferences in `reel.media.v1`. The list view (`LibraryList.tsx`) is an ARIA table on a CSS grid whose columns follow its own width (container queries); `TitleRowWide` in the same file is the row on collection pages. Detail pages are deliberately untouched: their hero fills the viewport so the ambient clip plays across the whole screen.

### Audiobooks

Audiobooks are a separate model from movies/TV (`Audiobook*` types, not `ReelTitle`) — `lib/jellyfinAudiobooks.ts` reads Jellyfin `AudioBook` items (a **Books** library, one M4B per book). Jellyfin 10.11 does not return chapter markers for audiobooks, so they are read with `ffprobe` over the Direct Play stream and cached in the SQLite `settings` table (`audiobook.chapters.<id>.<size>`); Jellyfin's own `Chapters` win if a future release provides them. Playback is *not* `JellyfinPlayer`: `app/_components/media/audiobooks/AudiobookPlayer.tsx` is a provider mounted in `MediaShell` (outside `PageTransition`) that owns a single `<audio>` element so a book keeps playing across navigation; `PlayerChrome.tsx` renders the docked mini player and the full now-playing sheet. Resume position lives in Jellyfin (progress reported through `/api/jellyfin/report`); only the loaded book id, speed and volume are in `localStorage` (`reel.audiobook.v1`).

### Books (reading)

The Books rail entry has two halves: **Listen** (`/media/audiobooks`, above) and **Read** (`/media/books`). Readable books are Jellyfin `Book` items (PDFs in a second Books library, laid out `Author/Title/Title.pdf`) — `lib/jellyfinBooks.ts`. Jellyfin only indexes them, so: the author falls back to the grandparent folder name, a `Level N` tag becomes the graded-reader level filter, covers are rendered from page 1 **in the browser** and posted to `/api/jellyfin/books/[id]/cover`, which stores them as the item's Primary image, and the reading position lives in the SQLite `settings` table (`book.progress.<id>`), not Jellyfin. The reader (`app/_components/media/books/BookReader.tsx`) uses `pdfjs-dist` (legacy build); its worker, CJK cmaps, fonts and wasm (plus the Documents reader's `pdf_viewer.css` and its images) are served from `node_modules` by `app/api/pdfjs/[...path]` and the PDF itself is range-proxied through `/api/jellyfin/books/[id]/file`.

**Read-along narration:** Jellyfin resolves a `Title/` folder to the Book and ignores an MP3 placed beside the PDF, so a book's narration lives in the *Audiobooks* library at the same `Author/Title/Title.mp3` path. `folderKey()` in `lib/jellyfinBooks.ts` pairs them (`Ebook.audioId`); the reader plays it through the persistent audiobook player (play / back 5 s / 1×·0.8×·0.6×, speed remembered per book), and `getAudiobooks()` leaves paired narrations off the Listen shelf, Home and search.

**Narration timings (karaoke-style read-along):** `scripts/sync-narration.py BOOK.pdf NARRATION.mp3 OUT.json --upload http://HOST:3000 --book <jellyfin book id>` runs **offline on a fast machine, never on the Pi**: faster-whisper (word timestamps, the book's vocabulary passed as `hotwords` so it spells like the book; windows kept independent because carrying context makes it loop), lines re-cut at real pauses, then each line placed on a page by comparing *hiragana readings* (pykakasi) with a length-weighted monotonic DP. Page text comes from the PDF text layer, else macOS Vision (`scripts/ocr-pdf.swift`, horizontal only), else Tesseract `jpn_vert` for vertical Japanese. Below 0.70 confidence every line gets `page: 0` (captions only, no auto page turns). Spelling: the title/author (`--names`) and the book's most frequent kanji/katakana words go to Whisper as hint words; afterwards any transcript word that *reads* the same as a name or recurring book word but is spelled differently is corrected automatically (猫股→猫又), and `--fix wrong=right` covers what can't be derived (ズレズレ草→徒然草). For pages without a text layer the Tesseract run also yields character positions (`pageChars`, page fractions): Tesseract's per-character boxes are broken for vertical text, so word boxes are split evenly along the reading direction and words are kept by thickness relative to a Japanese-weighted median (drops furigana and illustration junk). Timings are stored in the `settings` table (`book.sync.<id>`) via `/api/jellyfin/books/[id]/sync`. In the reader, `ReadAlong.tsx` draws a multiply-blended highlighter over the printed words (from the PDF text layer, or the timings' OCR'd `pageChars` when the layer holds almost no Japanese — a bare page number counts as none; `pageChars()` in `pdf.ts` skips furigana by type size, and an LCS aligns transcript to page), shows a caption strip or a large-type side panel, and turns pages 0.6 s ahead of each line.

### Photos

Family photos/videos (`docs/photos-spec.md`) are plain files under `PHOTOS_ROOT` — a NAS share the Pi only mounts — indexed into the `photos` / `albums` / `album_items` tables of the same SQLite db (`lib/photos/db.ts`; `getDb()` from `lib/db.ts`). `lib/photos/scan.ts` is a `globalThis` single-flight scanner (started from `lib/startup.ts`, then every 6 h, after uploads, and on `POST /api/photos/scan`): it walks the share (skipping dot-entries, `@eaDir`, `#recycle`), only re-reads files whose size/mtime changed, re-links moved files by a cheap hash (sha1 of size + first 1 MiB + last 64 KiB), and marks vanished files `.missing/…`. **Mount guard:** the first scan of a non-empty library writes `PHOTOS_ROOT/.photos-library`; if that marker is gone (or the root is unreadable) while the index has rows, scans abort with `libraryOnline: false` instead of treating everything as deleted. Favorites, albums and tags are mirrored, keyed by `rel_path`, to `PHOTOS_ROOT/.library/catalog.json` (debounced 5 s, `lib/photos/catalog.ts`) and imported when those tables are empty (fresh Pi). **Tags** are free-form (`photo_tags`, keyed by photo id so they follow trash/restore/moves): stored as typed but matched through a lower-cased `tag_key` (normalisation in client-safe `lib/photos/tags.ts`, unit-tested), edited per item via `PATCH /api/photos/[id] { tags }` and in bulk via `POST /api/photos/tags`, and filtered with `GET /api/photos?tag=` (the timeline keeps it in `?tag=`). Metadata: sharp + `exif-reader` (HEIC containers too), ffprobe for videos (`lib/photos/meta.ts`). Thumbnails (`t` 400 px, `p` 1600 px, video `poster`) are made lazily into `PHOTOS_CACHE/<id>/` by `lib/photos/thumbs.ts` through a 2-slot priority queue (requests before background fill); HEIC is decoded with ffmpeg: iPhone files are a grid of 512 px HEVC tiles plus auxiliary images (depth map, portrait matte), and ffmpeg 7.x picks one tile or the matte on its own, so `heifFrame()` reads the grid geometry with `ffprobe -show_stream_groups` and stitches it (concat → tile → crop), then applies the EXIF orientation sharp reads from the container. Upload also writes the mount-guard marker, and a missing marker self-heals when indexed files are present on disk. Uploads/trash/restore live in `lib/photos/store.ts` (uploads go to `YYYY/MM/` by capture date, trash is `PHOTOS_ROOT/.trash/<original path>`). Routes are under `app/api/photos/**`; `/[id]/stream` is a capped (2) live H.264 720p transcode killed on disconnect. Thumb URLs are `immutable`, so the UI appends `&v=` when an item changes; a decode failure leaves a `failed` marker in the item's cache folder until the file's mtime changes.

**Photos UI** (`app/media/photos/**`, components in `app/_components/media/photos/**`): the timeline (month sections, keyset infinite scroll, filter chips, year/month jump list, select mode with long-press / shift-click), the lightbox `PhotoViewer` (opened with `?v=<id>` through the History API so Back closes it — passing `history.state` back to `pushState` silently skips Next's `useSearchParams` sync, always pass a fresh object; images show the `p` preview and load the original only on zoom; videos fall back from `/file` to `/stream?t=` when `canPlayType` rejects the codec), the batch `Uploader` (XHR per 10 files, cancel, `beforeunload`), albums, Recently deleted, and `MemoriesRow` on the media Home ("on this day" from earlier years, else the newest). A "Library offline" banner appears whenever the mount guard reports the share missing.

### Documents

The family file store (`docs/documents-spec.md`): a Finder-style browser at `/media/documents` (the old `/files` redirects there) over real folders on the NAS `documents` share, mounted at `FILES_ROOT`. The API is `app/api/files/**` on top of `lib/files.ts`: `list`, `search`, `content` (Range), `upload` (never overwrites, 409), `mkdir`, `rename`, `move`, `delete`, plus `thumb` (WebP `t` 320 / `p` 1280 px: sharp for images, the Photos HEIC decoder `decodeHeifFrame`, PDFs page 1 via `pdftoppm`; cached in `FILES_CACHE` keyed by sha1(path + size + mtime), generated through the Photos 2-slot `runLimited` queue, a `.fail` marker remembers undecodable files, a missing `pdftoppm` is remembered for the process lifetime → 404 `No preview`), `stat` (bounded recursive totals for the delete confirm) and `status` (`{ online, root, disk }`). Dot-entries, `#recycle`, `#snapshot`, `@eaDir` and `*.part` are hidden everywhere (`isHiddenName`). **Mount guard:** with `NAS_REQUIRE_MOUNT=1` a root that is not a mount point (`lib/mount.ts`: same `st_dev` as its parent) is offline — every `/api/files` route answers 503 `{ error: 'Storage offline', offline: true }` (mutating routes after `assertSameOrigin`), and Photos' `checkLibraryOnline()` / scan treat `PHOTOS_ROOT` the same way. A missing root is offline even without the flag.

### Color system

`StatusColor` (`good` → `hazardous`) is the single shared type that drives border classes, value text, sparkline stroke, and AQI badge color. All of it comes from `lib/statusColors.ts` (hex, label, text/border/badge/background classes). Hex values:

```ts
{ good: '#34d399', moderate: '#facc15', sensitive: '#fb923c',
  unhealthy: '#ef4444', 'very-unhealthy': '#a855f7', hazardous: '#e11d48' }
```

(`hazardous` was `#9f1239`, which measured 2.5:1 on the dark background; `#e11d48` is 4.2:1.) Metric cards also show the status word, never colour alone.
